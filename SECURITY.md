# Security policy

## Supported versions

Security fixes go into the latest release. Please make sure you can reproduce the problem with
the latest build.

## Report a vulnerability

**Please don't report security problems in public issues, discussions or pull requests.**

Report privately, either:

- through GitHub: **Security › [Report a vulnerability](https://github.com/aidevs-pt/ffmpeg-builds/security/advisories/new)**, or
- by email to [security@aidevs.pt](mailto:security@aidevs.pt).

Include what you found, the affected release and platform, steps to reproduce it, and the impact
you expect.

## What happens next

- We acknowledge your report within **3 working days**.
- We confirm the problem and agree on a fix and a disclosure date with you, usually within
  **90 days**.
- We publish a security advisory with the fixed release and credit you, unless you prefer to stay
  anonymous.

## Scope

In scope: the build scripts and workflows, and how the binaries are configured, built and
published, such as a source that isn't verified or a build option that exposes users.

Vulnerabilities in FFmpeg or one of the libraries it builds belong with that project. We publish
a new build once a fixed release is available.

Thank you for helping keep these builds and their users safe.
